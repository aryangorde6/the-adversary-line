## Reading the code for checks that answer a check

Read `src/model.js`, `src/store.js`, `src/time.js` and `src/domain.js` at this commit.

- `MINUTE_BOUNDS` in `model.js` is `slot_minutes {min 1}`, `reservation_duration_minutes
  {min 1}`, `cancellation_cutoff_minutes {min 0}`, and every `max` is `undefined`. There is
  no ceiling anywhere in the file and no occurrence of `10080`. The absence of a maximum is
  a real absence, not a disabled check.
- `minuteSettingProblem` is the single place a minute setting is judged, and the import
  validator calls `hasValidMinuteSettings`, which calls the same function. The two doors
  cannot drift apart without the shared function changing.
- `isRealLocalMinute` in `time.js` checks the bare-local shape, then a real calendar date,
  then `hour > 23 || minute > 59`. It never calls `resolveLocal`, which is why a gap time
  imports. That is the ruled behaviour, reached by construction rather than by a
  special case.
- `domain.js` decides the grid question in `outsideOpeningHours` first and the grid question
  afterwards, with a comment saying so. No check name, ticket reference or fixture id
  appears in `src/`.
- `restaurantName` falls back to the literal "this restaurant" when a restaurant has no name,
  which is the person-facing wording and not a check-shaped branch.
